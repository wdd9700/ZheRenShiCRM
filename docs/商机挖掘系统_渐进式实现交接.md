# AI 商机挖掘与客户资源管理系统｜渐进式实现交接

> 文件性质：**方向与交接材料，不是冻结的 PRD、架构规范或动工指令。**  
> 文档状态：初始交接稿｜2026-10-31  
> 接手对象：Coding Agent / 技术负责人  
> 配套文件：`AGENT.md`（工作协约）、`DECISION_LOG.md`（决策链）  
> 工作原则：**先验证需求和复用路径；先形成可靠的信息存量与时间线，再逐步智能化。允许临时决策、持续纠偏。**

## 0. 请先读：哪些内容已经确认，哪些还不能写死

### 已确认的产品方向（需求共识）

1. 业务出发点是 CEO 已积累的人脉、组织、商会、企业通讯录和实际客户沟通；现有数据散落在表格、通讯录、笔记和个人记忆中，难以调用和同步。
2. 核心目标不是「做一个 AI 聊天框」，而是让**客户资源、公司资料、沟通与跟进、商机/项目状态**能够被保存、查询、持续更新和追溯。
3. 优先**调查并复用现有开源 CRM 的后端业务逻辑与能力**，选择性采用；不预设从零开发整套 CRM，更不预先绑定某个仓库。
4. **先能存、能查、能改、能导入导出、能跟踪，再做半智能分析，最后做主动式助理。** 不能把录音转文字与大模型分析当成第一阶段的前置条件。
5. 面向团队的集中服务端、多用户身份、私域/团队权限隔离与共享数据是架构基线；首轮允许用单用户合成数据做最小可操作烟测，但不把单用户作为架构前提。客户端优先复用响应式 Web/PWA，后续再按证据评估桌面/移动薄封装与日程导入同步。
6. 演示可以呈现后续设想，但必须清晰标识「已实现」「原型/预览」「待验证」，不能用假的交互让人误以为已交付。
7. 客户资源私域与正式业务档案需要有明确边界。CEO 私人备忘、主观评级等不能默认对普通业务成员可见，也不能自动同步至正式客户档案。
8. AI 是可核验的信息整理与建议层，不拥有未经确认修改重要业务事实、自动报价、签约或对外承诺的权力。

### 当前明确不固定的决策（由 Agent 调研、实测、阶段性决定）

- 具体 CRM 基座、是否整个系统部署、只复用其 API/数据库层还是开发扩展模块。
- 前端技术栈、后端语言、数据库、搜索索引、任务队列、部署方式和服务拆分。
- 业务对象精确字段、商机阶段名称、项目管理粒度、智能体框架和模型供应商。
- 团队权限作为首轮门槛的具体规则，以及日历协同和半智能化能力按真实反馈的实现顺序。

对上述问题，**Agent 应主动调查并做可回退的临时选择**，随即写入 `DECISION_LOG.md`，而不是把工作停在等用户指定技术栈上。

## 1. 业务问题与使用者

### 业务场景

CEO 通过行业活动、商会、组织和个人关系认识大量企业与联系人。现阶段需要解决：

- 「认识谁、在哪认识、与哪家公司关联、主营什么、可能需要什么」长期散落、重复或过期。
- 接触企业前缺少成体系的背景准备；沟通后信息分散，下一次跟进靠个人记忆。
- 一个客户可能有多个场景，但在传统的简单表格中容易被压成单条“客户状态”。
- 成交、未成交、推迟和技术交付中的经验缺少跨案例沉淀；但经验沉淀应以真实记录为基础，不能凭空造“行业方法论”。
- 将来团队成员日程不同、共同空闲时间难协调，但私人安排不应被分享成详细业务信息。

### 用户阶段

- **首轮**：团队架构下的最小验证，可先用一个受控账号和合成数据验证录入/检索/追踪体验；必须保留多用户身份、权限隔离和共享数据的服务端演进路径。首轮单账号不是团队权限验收。
- **后续**：CEO、授权核心成员、业务执行者、交付人员。不同角色可以看到不同范围；绝不默认“同一组织中的所有账号拥有所有联系人数据”。

### 一条业务链路（方向性，不是唯一合法状态机）

`资源导入/录入 → 企业和联系人归集 → 业务事件记录 → 场景/需求线索 → 商机推进 → 成交/未成交 →（如成交）交付项目 → 复盘沉淀`

后续 AI 可在各节点提供企业预研、会议整理、缺口提示、类似案例推荐、价值测算与行动建议，但它不是前述数据链路成立的条件。

## 2. 已有输入与第一份数据样本

已有一张企业资源表头截图（**只有表头，没有可直接导入的真实记录文件**），字段为：

| 序号 | 姓名 | 公司名称 | 联系方式 | 公司产品、服务 | 需要的产品、服务 |
|---|---|---|---|---|---|
| 不一定要保留为业务主键 | 联系人 | 企业 | 手机/微信等，待按实际格式确认 | 企业提供什么 | 需求线索，不直接等于已成立商机 |

这组表头可作为**字段映射与导入能力的第一条验收样例**。不应假设用户已经提供了整份 Excel，不得虚构真实客户行。

导入设计应允许：预览、映射列、检查重复、人工确认、报告失败行、尽量避免重复导入产生新记录。第一次做不到自动合并也可以，但应有明确的人工消歧方式。

## 3. 业务对象：建议分离概念，不强制照此建表

下表表示**语义边界**。优先映射到所选开源 CRM 的已有对象，能复用就不要另造 ORM/模型；是否需要自定义实体以试运行结果决定。

| 业务概念 | 主要含义 | 易混淆处 |
|---|---|---|
| 资源 / 来源 | 认识背景、归属组织、推荐关系、个人关系线索 | 不等于正式客户；受更严格的私域访问约束 |
| 人物 / 联系人 | 姓名、联系方式、职位及多企业关联 | 联系人不一定是单一企业的永久员工 |
| 企业 / 组织 | 公司主体、主营业务、公开资料及其来源 | 组织名单和公司主体并非完全等价 |
| 沟通 / 业务事件 | 会议、电话、拜访、备注、客户反馈及发生时间 | 业务事件不是数据库字段修改日志 |
| 需求 / 场景线索 | 企业表达的需要或我方发现的机会假设 | “需要 AI 质检”不等于立项或确定报价 |
| 商机 | 机会的负责人、推进状态、约定行动及结果 | 同一企业可有多个商机；不能用一个企业状态覆盖所有商机 |
| 交付项目（可选） | 成交之后的实施、验证、验收、维护节点 | 销售商机生命周期 ≠ 实施项目生命周期；第一版不必开发完整项目管理套件 |
| 待办 / 跟进 | 下次联系、演示材料、任务期限、提醒 | 确定性的提醒应由应用逻辑处理，不靠模型“记住” |
| 原始资料 / 来源记录 | 文件、纪要、转写文本、人工填报及对应位置 | AI 摘要不能覆盖原文，也不能伪装成客户确认的事实 |
| 日程忙闲（后续） | 公司事件和私人时间占用 | 私人忙闲可共享，私人事件细节默认不共享 |

可逐步探索的附加字段：数据来源、确认状态、修改人、事件发生时间/录入时间、附件引用、关联对象、可见范围。不要为了以后可能用到的字段现在一次性做完。

### 两种动态信息

1. **动态存量（Snapshot）**：当前企业、联系人、商机和任务是什么状态。
2. **动态时间线（Timeline）**：哪些业务事件让我们知道了更多，何时发生、谁记录、和哪个对象相关联。

补充：**审计/变更历史（Audit/Version）**是第三种概念，例如谁把商机阶段从“沟通中”改为“暂缓”。选型时检查基座是否已有审计与恢复机制，不必在第一版自行发明完整事件溯源系统。

## 4. 分级实现路线（工作假说，允许根据试用重排）

下述每级都有独立价值。任何更高级功能不得破坏较低级已经建立的确定性数据管理能力。

### L0｜基座调研与可运行最小样板

**要回答的问题**：能否以低成本复用成熟 CRM 的客户管理、关联、时间线、数据导入和扩展接口？

- 至少比较重点候选 **Frappe CRM、Twenty**，并按需要抽查其他候选；尽量在真实环境中部署/试用，而非只看营销页。
- 重点核对：支持的部署方法、维护情况、最低硬件、版本兼容、数据导入、对象与关系扩展、活动时间线、API、认证、权限、备份/导出及许可证。
- 做一个可以实际点选、操作的数据路径，不先写庞大后端抽象层。
- 给出短小的评估记录和**暂定方案**；把未验证项标为未知，选择理由写入决策链。

**阶段出口**：用户能看到一个可启动/可复现的选型样板，并理解“复用什么、未复用什么、为什么暂选它”。

### L1｜团队架构下的存量信息管理（首要能力）

- 人物、企业、联系信息及基础关系的新增、查看、编辑、检索。
- 能映射上述表头进行 CSV/XLSX 导入（优先复用基座已有能力），处理重复记录和失败行；支持基本导出。
- 可写入企业提供的产品/服务和需求线索；能把私人资源备注与正式业务资料在数据层或至少清晰的权限标识层区分。
- 支持重新打开、重启后数据仍在；具备最低限度备份/恢复验证。

**阶段出口**：不调用 AI，仅靠这个应用就比继续使用分散表格更容易查询和更新客户资料。

### L2｜业务事件时间线与商机生命周期（基础 CRM 闭环）

- 能给人物、企业或商机添加有时间戳的沟通、备注、拜访及待办事件。
- 支持一个企业关联多个需求线索/商机，每个商机独立推进、记录下次行动和结果（成交、未成交、暂缓等可调状态）。
- 必要时从已成交商机关联一条轻量的交付项目记录；不要求完整工时、财务、甘特图。
- 重要更新可追溯，且避免因为修改当前字段就失去关键历史事件。

**阶段出口（第一轮核心可操作 Demo）**：导入/建立企业与联系人 → 补一条需求 → 形成一个商机 → 记录一次沟通 → 设置下次跟进 → 更新阶段 → 在时间线上查看演进。整条流程不依赖 AI。

### L3｜时间段级日程安排与团队协调（权限基线前置）

**当前有效目标**：用户已将自主迭代授权延伸至完成 L3（D-007）。L1/L2 的团队安全与业务闭环仍须修复并全流程验收，未通过不得称完整交付；可并行准备 L3。以下为待实现/待验证的出口要求，不是已交付能力。

- **日程不等于日历**：日历只是展示视图；待办截止时间只表示期限，不自动占用时间。实际日程必须有开始/结束时间、明确时区与忙/闲状态，允许分钟输入，不硬定只能 30/60 分钟；支持日内多段独立安排与跨日时段，校验结束晚于开始。
- **时区与冲突**：新增日程保留明确的时区语义，跨时区显示与忙闲计算须对应同一实际时刻；不得擅改现站 `Asia/Kolkata` 历史语义或迁移旧历史时区。重叠先提示，不自动移动或取消他人安排。
- **协作与私域**：团队业务安排明确拥有者、参与者、可见与编辑授权；可共享被授权的商机进度。私人安排对其他成员最多暴露忙闲占用，不泄露标题、正文或关联私密信息；共同空闲查询同样遵守该边界，父业务对象可读不自动意味着日程可编辑。
- **导入与同步**：先验证本地创建与合成 ICS 单向导入，不依赖第三方账户。导入须预览确认，定义来源/事件标识、更新与取消的匹配规则；重复导入不新增副本，歧义不静默覆盖，失败逐项可见、可安全重试且不破坏已成功记录。未支持的格式/重复规则须明确拒绝或报告，不伪称完整 ICS 支持。后续连接前另行明确只读导入/单向/双向、变更与取消传播、冲突及失败恢复；未获授权不得自动连接私人账号或外发邀请。

**可验证阶段出口（须保留 UI/API 与持久化证据）**：

1. 两名普通成员各自创建、修改、取消具体时间段安排；覆盖分钟级输入、日内两段、跨日、非法起止及重启后读回。取消后释放占用，非授权成员不能修改他人安排。
2. 用合成数据验证两个明确时区下同一时刻的转换（包括跨日显示），重叠提示、相邻不重叠边界及取消/修改后的忙闲更新。查询两人的指定日期范围、时区及最短时长下的共同空闲区间，结果与合成占用一致；日期格子或待办期限演示不能替代。
3. 双账号从页面、直接接口、列表/搜索、导出及忙闲查询核验：私人安排仅露忙闲、无标题正文；授权业务安排可协作，撤权后不可继续读详情或编辑。服务端权限不能仅靠隐藏 UI。
4. 合成 ICS 覆盖首次导入、重复导入、同来源更新/取消、时区、坏事件与失败重试，逐项结果可复核。实际第三方同步须有真实凭据和明确授权，再独立验证同步方向、重复/冲突及失败恢复；未连接时如实标注未验证，不编造完成，也不以此阻塞本地与合成导入出口。

> L4/L5 保留为后续方向，不混入本轮完成承诺；小规模信息提取试验不替代 L1–L3 验收。

### L3.5｜CRM 与日程业务关联（历史规划，不在 v1.0）

> 当前范围按 D-001 的 2026-11-05 用户决定：v1.0 仅 L0–L3、Windows 使用端与团队集中服务端。下述 D-009 原话及顺序保留历史，不是当前开工授权或 v1 验收前置；本文其他“新增 L3.5”表述亦按此替代关系理解。

**用户决定与开工顺序（D-009）**：原话“对的，那就叫L3.5，排在L3实现之后、L2测试没问题之后，测试L3和实现L3.5并行推进”。开工必须同时满足 **L3 约定功能实现完成**（不只是局部后端完成）和 **L2 业务/权限验收无未解决阻断**。随后测试 L3 与实现 L3.5 并行，不要求 L3 全验收通过才开工；门槛未满足不得提前编码。本次仅记录路线，不代表 L2/L3 已完成或门槛已满足。

- **受控业务关联**：日程可关联企业、需求、商机与任务。业务/任务负责人按原有权限读取原记录，不将敏感摘要复制到日程绕过权限；关联本身不授予任何一侧的读写权限，撤权后重新校验，不能因日程可见而暴露不可读业务信息。
- **目的与结果分离**：活动目的（如需求澄清、方案沟通）说明打算做什么，不是业务结果或已确认客户事实；会后结果单独记录，由有权限的人明确人工确认后写回对应业务时间线，不以日程结束/取消自动认定业务进展或任务完成。
- **责任分工**：区分业务/任务负责人、日程牵头人和参与者分工；安排谁组织、谁参与，不自动改派业务负责人或授予编辑权。日程占用与任务期限仍各有语义。
- **隐私与非目标**：忙闲投影不含业务摘要、关联详情或会后结果；关联/确认/写回均须服务端校验权限并可追溯。不靠 L4 AI 才能成立，不引入完整项目管理、自动改阶段/自动外联。

**后续验收方向（尚未执行）**：双普通成员从原业务记录进入关联日程，按授权核验负责人读取与牵头/分工；未授权或已撤权者无法经关联、忙闲及写回旁路读写业务；活动目的不被当成业务结果，未经确认不写时间线，确认后可追溯且不误改任务状态。实现契约由对应 owner 后续细化，本路线不修改其契约或替代 L3 测试。

### L4｜半智能化辅助（明确在人类确认之下）

- 可选地接入录音**已有转写文本**、会议纪要、聊天记录等资料；抽取企业、联系人、需求、行动项，并在写回前由用户确认。
- 企业基本公开资料检索、来源标注；客户沟通摘要、信息缺口提醒和相似案例检索。
- 简单商机价值初算：现金节省、工时/产能释放、损耗降低、新增收入/毛利、风险变化分开呈现，标注假设与证据。
- 信息状态区分：来源支持的事实 / 客户明确表达 / 我方判断 / AI 推测；保留原始材料。

**阶段出口**：AI 能减少人工录入/阅读负担，但无法在未经确认时改写关键事实或承诺。

### L5｜主动服务与跨案例经验复用（远期）

- 根据历史信息和日程提出“今天值得联系谁、为什么、带什么材料”；建议而非自动外联。
- 识别客户之间的相似场景、长期未推进的商机、信息缺口与历史经验；给出可追溯证据。
- 在已有真实案例之上逐步积累行业方法论与交付经验；**不预设凭空生成的案例库**。
- 引入 Agent 编排、定时任务、外部工具前，先评估成本、可解释性、权限和误操作防范。

**阶段出口**：经过实际用户验证，主动建议能提高业务效率而不是制造信息噪声。

### 明确暂缓的非目标

全面 ERP、HR、财务、跨部门审批、复杂项目排期、自动报价/签约/外联、大规模经营驾驶舱、未经许可的客户资料训练或跨客户复用；后续只有真实业务需求和授权时才重新评估。

### 候选的比较方法（比“星数 / 宣传口号”更重要）

优先比较以下实际任务，记录可复现证据，而不是预先制定硬性评分：

1. 本地启动是否可复现；基础运行资源和依赖是否可接受。
2. 按截图列名导入/映射数据是否顺畅，是否能避免重复导入与错误关联。
3. 联系人与公司关联、公司与多个机会关联，是否自然，是否需要改底层核心表。
4. 商机阶段、业务活动、待办提醒、历史变更是否有现成可靠支持。
5. 能否隔离 CEO 私人备注和业务档案；未来实现多用户权限的成本如何。
6. 扩展一个“场景线索”或“轻量交付项目”所需的代码/配置规模。
7. API、导出迁移、备份恢复、持续升级成本以及 AGPL/GPL/混合许可义务。

优先复用的粒度可以是：**完整平台部署、通过 API 外接模块、官方扩展机制、自研轻薄外壳、仅借鉴实现方式**。不要因为“开源可见”就默认可以无成本摘取代码或避免许可证义务。

## 6. 给 Coding Agent 的推进方式

1. **开始时先做一次方向澄清**：阅读这些文件和现有仓库，概括业务目标、首个可操作闭环、不会做的内容、已知未知；只问真正影响目标/权限/敏感数据边界的少数问题。
2. **先调查现状再改**：找出仓库已有服务、依赖、数据库、部署与测试方式；不要假设这是空白项目，也不要照搬这份文档的字段名称。
3. **技术选择暂定即可推进**：涉及较大、可回退的技术栈或架构选择，比较 2–3 个现实备选，选一个临时最合理的方案，**决定之后立刻把备选与理由写进 `DECISION_LOG.md`，再继续开发**。
4. **持续核验而非一次定死**：实际发现某开源 CRM 对私域/商机/扩展不合适，应记录事实并改选；更新本交接文档中被证伪的假设，不要为了维护初稿而迁就架构。
5. **先跑通真实可用的端到端路径**，再装饰 UI、做智能体和复杂系统设计。
6. **阶段验收必须举证**：运行方式、界面或接口可操作路径、测试结果、已实现与未实现边界、迁移/备份方法。
7. **交付前主动回看完整决策链**，提交“做了什么 / 为什么 / 需要用户决定什么 / 低置信度推荐 / 推荐理由 / 为什么不能自己临时决定”的报告。具体格式见 `AGENT.md`。

### 高风险边界（不要以“自主推进”为由越过）

- 真实客户资料、联系人、录音、商业秘密的共享、外发、第三方模型处理与部署位置；使用前确认授权与保密约束。
- 对公网开放的真实数据必须有合理认证和访问控制；本地假数据演示可简化。
- 重大、难回退的生产数据迁移/删除、真实客户自动触达、对外合同承诺、显著付费或不可逆的许可/合规选择，需要用户确认。
- 不得把 LLM 的推测写为客户事实，不得自动覆盖原始记录；重要数据修改留追踪路径。

## 7. 交接后的首轮产出建议（不是预设工期）

**首轮不要直接交“整套设计文档”**；建议交：

1. 一个短的方向校准纪要：目标、边界、首个可操作闭环、尚不确定项。
2. 一份对现有仓库/运行条件及开源候选的**实测记录**（包括筛掉什么和为什么）。
3. 一个可运行的基础数据闭环：导入 / 查询 / 编辑 / 关系 / 沟通事件 / 下一行动 / 时间线；可分增量提交。
4. `DECISION_LOG.md` 的真实决策记录和一份交付回顾，而不是只有“技术栈已确定”。

**成功标准**：用户即使关掉所有 AI 功能，也能可靠地保存客户信息、更新商机状态并追溯业务过程；未来接入 AI 不需要重做整套数据基础。
