# M9 候选 e7ef 浏览器验收（D030300）

## 结论

**本轮不是完整验收通过。** 两个新销售账号通过正常网页表单登录并通过网页菜单注销；合成 A 创建的 Lead、Private Note 和 Private Task 有保存及回读证据，B 的活动列表未显示 A 的两个私密活动。上述业务操作发生在内置浏览器的**后台标签**，不等于用户可见窗口的验收。未完成 B 对 Lead 详情的授权判断、显式共享/撤权、商机推进、真实可见跨标签及 BFCache 测试。

A 正常注销后、以及随后 B 登录后，先前未刷新的 A 详情标签依旧显示 A 身份和 Lead 内容。此为后台旧 DOM 残留，**不证明匿名或 B 可以向服务器读取该记录**；真实可见标签恢复和 BFCache 的行为未验证。候选的注销清屏要求仍需回归。

1. A 网页表单提交后进入 `/crm/`，初次身份确认界面超过20秒，随后页面显示 `M9 e7ef synthetic A` 和 Lead 空列表。经创建弹窗输入唯一标记并正常点击创建，进入 `CRM-LEAD-2026-00005` 详情，名称和 A 负责人可见。刷新后身份确认超过30秒；其后重新观察旧标签已是该详情，因此仅能说**最终刷新回到详情，耗时和等待原因未确定**。筛选未测。
2. 活动管理页分别创建 `D030300-A-Private-Note` 和 `D030300-A-Private-Task`：Private、无协作者/任务受派人，父类型 CRM Lead、父编号 `CRM-LEAD-2026-00005`；各显示保存成功。分别点活动页刷新并再次点击列表项，回读标题、正文及父编号。两活动的系统对象 ID 未在页面显示，不能推测。
3. A 通过活动页账户菜单 `Log out` 得到成功注销页；B 用正常表单登录后，活动页账户菜单显示 B，Note 和 Task 分类各显示可读活动0。B 直接打开 A Lead 详情后身份确认超过30秒，未等到明确拒绝或内容，故详情授权为未决；未声称完整双账号隔离通过。
4. A 注销后旧 A 标签保留身份和 Lead；B 登录后该旧标签仍保留。没有模拟 visibility/focus/pageshow 或声称真实 BFCache；没有对该旧标签执行匿名业务请求。
5. B 最终通过页面菜单注销，页面显示成功；本人两个标签均已关闭，其他现有标签未碰。无业务对象删除。
