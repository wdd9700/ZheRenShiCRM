# 独立浏览器验收报告（2026-11-03）

## 结论先读

**本轮不是“全流程验收通过”。** 管理员的六列CSV导入小闭环已实测成功，但线索列表/详情的权限一致性、跨标签注销后的旧数据残留、Private活动保存失败需要优先处理。普通销售的完整业务闭环及双账号权限矩阵尚未通过。

本报告来自用户指定的fork验收会话，仅测试与记录，不代替原主控迭代。没有修改产品代码、部署新版本、调整权限或接管Tower。

### 确实跑通的关键链路

1. 正常登录表单 → Administrator登录 → 管理员导入页。
2. 本地合成CSV → 页面文件选择上传 → 共享确认 → 逐行预览 → 最终确认 → 导入结果。
3. 三行输入得到：**成功1行、文件内重复复用1行、缺少姓名失败1行**；前两行指向同一Lead/企业/联系人。
4. 下载失败行CSV并读取核对来源行号和原因。
5. 点击导入结果中的真实Lead链接，进入 `CRM-LEAD-2026-00010` 的实际详情，看到合成人员名称、负责人、状态、活动区及转换入口，而非只验证HTTP200或应用外壳。
6. 普通测试A被导入入口拒绝；原生注销、单次无效登录提示、管理员有效登录正常。

## 2. 发现与复现步骤

### F01：列表显示详情无权读取的Lead

前提：合成A会话，18088入口。

1. 打开CRM线索列表，观察到6条历史合成记录。
2. 点击 `TEST-C010800-TEAM-20261102163350B` 对应行。
3. 进入 `CRM-LEAD-2026-00009`。
4. 页面报错：`控制器权限检查未通过 用户c010900-test-202611030044-a@example.invalid无此文档访问权限: CRM线索 - CRM-LEAD-2026-00009`。
5. 返回并刷新列表，摘要仍可见。

预期：同一身份、同一授权时点，列表不应持续展示详情已判定无权访问的记录摘要；若为旧缓存，应失效并不再呈现。

实际：列表摘要与详情拒绝不一致。**不是仅凭B命名推断私域记录**，有同一A身份的详情拒绝证据。

证据：E07、E08；关键快照 `text-b6741a0e-e796-40ea-bb62-3448e010bc2c`。

待定位：检查实际部署版本、列表网络响应、账户切换后的缓存命名空间/持久化数据、过滤和重新获取时序。上述均为排查方向，不是本轮已确认根因。

回归：在独立A/B上下文及共享授权矩阵下测试列表、详情、搜索、刷新、失权和切换；不仅验证详情403。

### F02：注销及账号切换后旧标签保留旧身份与数据

1. A打开两个CRM标签。
2. 在一个标签通过网站菜单正常注销，看到“您已成功注销”。
3. 该已注销会话只读身份接口返回403。
4. 读取另一个未刷新的旧CRM标签，仍显示A及6条旧线索。
5. 正常登录Administrator，再读取旧标签，仍显示A及旧列表。

预期：建议在注销/账号切换后通知同源其他标签锁页或清理业务界面；重新激活/获取数据时必须重新核验身份。

实际：后台旧标签存在可读残留。本轮未将该标签展示给用户、没有精确验证visibility/focus事件，也没有证明旧标签在匿名状态下成功请求新数据。因此不能宣称“注销后服务端仍放行”。

证据：E09、E13，`text-cb3d1e44-4e0e-4c94-ad4c-fae29ce8964f`、`text-d9c2ad3c-8875-4933-b172-4aef359fbb61`。

回归：明确跨标签失效预期；测试可见旧标签、后台标签恢复、浏览器后退及网络断开时的屏幕残留，同时校验服务端拒绝与客户端清理。

### F03：Private活动保存正例被泛化拒绝

场景A：A进入 `/team-activities` → 新建Private活动 → 填写合成标题/正文 → 默认FCRM Note、无父、无协作者 → 保存。

场景B：Admin已成功导入且读到新Lead详情 → 活动管理 → 新建Private → 标题 `QA-FORK-20261103-PRIVATE-NOTE-ADMIN` → 正文为合成沟通 → 父类型CRM Lead → 编号 `CRM-LEAD-2026-00010` → 保存。

两场景实际均显示：`请求被拒绝或失败；未保存。请检查授权和父记录。`。

预期：合法新建正例可保存并回读；失败应提供足以区分输入、身份、网络和服务端问题的安全提示。

影响：本轮无法继续通过新活动测试共享/撤回/协作者/历史等流程，不能将这些权限用例算作通过。

证据：E06、E12；Admin字段及结果 `elements-99c53acf-88d6-4113-a1e0-caf4b1c30034`、`text-ada536f9-b3ae-4f19-82c8-b86785575019`。

额外负例：A无父Shared经确认后同样失败，但由于Private正例也失败，不能单凭该拒绝判定无父Shared规则已验证。

待定位：取得正常保存请求的实际HTTP状态和脱敏错误、服务端日志及部署配置；不要未经证据直接重置权限或归因为某个常见错误。

## 4. 界面观察（非全部视为缺陷）

- 组织简介等处插入较长权限说明，业务字段周围的阅读负担较高，适合后续入口/界面讨论。
- Getting started在reload/新标签再次出现。本轮只Close，没有完成或Skip all，不认定为已完成引导仍弹出的错误。
- 商机/任务列表只见框架，无记录也缺少明确空态；原因未查清，不能据此认定请求失败。
- 数据面板过去30天为0，与列表总量可能范围/权限不同，不单独定为计数缺陷。
- 活动失败提示过于泛化，排查与用户自助恢复成本高。
