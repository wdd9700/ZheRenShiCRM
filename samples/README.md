# samples/｜合成数据样例（不含任何真实客户资料）

本目录所有内容均为**人工虚构的合成数据**，用于验证导入与业务闭环，可以直接提交到仓库。
这里没有真实企业、真实联系人、真实手机号或真实微信；号码全部是 `1380000000x` 形式的占位值，
邮箱全部是 `example.com` 占位域。**不要把自己的真实客户表格放进本目录。**

## m5-synthetic-six-columns.csv

来源：交接文档 `docs/商机挖掘系统_渐进式实现交接.md` 第 2 节的企业资源表头截图（只有表头，没有真实记录）。
本文件按那六列构造，列顺序与表头完全一致：

| 列 | 语义 | 导入去向 |
|---|---|---|
| 序号 | 原始行来源编号，不当作业务主键 | 写进来源备注，便于回溯原始表格 |
| 姓名 | 联系人 | `Contact`（企业联系人） |
| 公司名称 | 企业 | `CRM Organization`（企业/组织） |
| 联系方式 | 手机/微信/邮箱原文 | 原文保留在联系人备注；可解析出的手机号写入 `Contact` 电话子表 |
| 公司产品、服务 | 企业主营 | `CRM Organization.company_description` |
| 需要的产品、服务 | 需求线索 | `CRM Lead`（需求线索），**不会自动变成商机** |

编码 UTF-8、无 BOM、逗号分隔、首行是表头。用 Excel 打开另存时请选“CSV UTF-8”，
不要用 GBK，否则中文列名会乱码；用 Excel 的“CSV(逗号分隔)”另存会丢 UTF-8 编码。

### 这 8 行为什么这样设计

| 行 | 覆盖的场景 |
|---|---|
| M5-001 / M5-002 | 同一企业（企业甲）下的多个联系人 |
| M5-003 | 第二个企业（企业乙）及其联系人，联系方式里混有邮箱 |
| M5-004 | 同一联系人（张一）的**第二个不同需求**：一个联系人可以有多条需求 |
| M5-005 | 与 M5-003 **完全重复**的一行：验证重复联系人/重复需求不会产生新记录 |
| M5-006 | 错误行：缺姓名 |
| M5-007 | 错误行：缺公司名称 |
| M5-008 | 错误行：联系方式里没有任何手机号或邮箱，无法建立可去重联系人 |

预期导入结果（由 `tools/crm/` 的适配器给出，见 `docs/MVP_WORKFLOW.md`）：
2 个企业、3 个联系人、4 条需求、0 个商机、3 行错误。重复执行第 2 次应为 0 新增、0 错误之外的实质变化。

## 原生导入注意

Frappe CRM 原生 `Data Import` 一次只处理一个 DocType，且只在"更新已有记录"模式按
`name`/autoname 字段更新，没有基于手机号或邮箱的自然键去重，也不会从同一条 CSV 里同时建企业、联系人、需求。
站点调度器开启后（见 `docs/MVP_WORKFLOW.md` 第 2 节）上传→映射→预览→导入可用，但本样例直接用它会有三个后果：

1. 中文表头要手工逐列映射，且"需求/产品"两列没有可选字段；
2. "联系方式"列里的 `13800000001 / 微信 m5-demo-a` 会被 Phone 校验拒绝（实测报 `is not a valid Phone Number`）；
3. 同一文件重复导入会直接翻倍（实测同一 3 行文件两次导入产生 2 条同名同手机号线索）。

真正避免重复、保留原文、把需求落位的产品入口是 **M7 的六列网页导入**（`resource_import`，部署测试中、未验收）。
`tools/crm/m5_import.py` 只是历史合成实现：它只接受**与本文件完全一致**的内容
（`tools/crm/m5_guard.py` 内写死的归一化 SHA-256 清单，不接受自报哈希），另加企业名以 `M5`、
姓名以 `样例` 开头的行级检查；任何改动过的联系方式/产品/需求/来源都会被拒。
`python tools/crm/selftest_guard.py` 可本地自检（含"合法前缀 + 真实样式载荷必须拒绝"）。
原因：M6 已用两个真实 Sales User 的 HTTP 请求证实 FCRM Note 私密 detail/PUT 均 200、activities 泄漏未共享 note，
因此**不要把真实客户资料放进本目录的导入路径**。
